# Translations (i18n)

The UI text lives in flat YAML catalogs under `lang/`:

- `lang/en.yaml` — English, the **canonical** key set and the default language.
- `lang/pl.yaml` — Polish.

## Add a language

1. Copy `lang/en.yaml` to `lang/<code>.yaml` (e.g. `lang/de.yaml`).
2. Translate the **values** only. Keep every key unchanged and keep `{placeholders}`
   such as `{source}` or `{image}` exactly as they are — they are filled in at runtime.
3. Set `language: <code>` in `config.yaml` (or start with `--lang <code>`) and reload the page.

A key missing from your file falls back to English, then to the key itself, so a
partial translation never breaks the app. Emoji at the start of button labels are part
of the value — keep them so the buttons stay recognisable across languages.

## How it works

- `i18n.py` loads the active catalog merged over `en.yaml`.
- The server injects the merged catalog into the page as `const T = {...}`;
  `web/app.js` fills every element with `data-i18n`, `data-i18n-title` or
  `data-i18n-ph` from `T`, and uses `T['key']` in scripts.
- User-facing HTTP error messages are translated too. Console and log messages stay
  in English on purpose, so bug reports are readable by everyone.

## Contributing a translation

Open a pull request with the new `lang/<code>.yaml` only. Please do not include
screenshots that show real station logos (see `CONTRIBUTING.md`).
